W15期末 demo + 三件套繳交

三件套

① 程式碼 (GitHub repo)

  • 完整 Android 專案(可重現 build)
  • README 含 build 指令、相依套件、模型權重位置
  • 有訓練 notebook 一併放
  • 授權聲明(預設 MIT)
  • repo 取個有意義的名字(不要叫 final-project)

② 研究報告 (PDF, 10-15 頁)

八段式架構,每段必有:

  1. Abstract — 一段話講完問題與結果
  2. Introduction — 為什麼這題目重要 + 相關工作
  3. Method — 你的演算法 / 模型架構,有圖最好
  4. Experiments — 資料集、訓練設定、評估方式
  5. Results — 數據表 + 視覺化 + Confusion Matrix / mAP / 延遲表
  6. Discussion — 結果意義 + 跟 baseline 比較
  7. Limitations — 你的方法在什麼情境會失敗
  8. Future Work — 如果有更多時間 / 資料 / 算力會怎麼做
研究級門檻(這兩個沒做的話拿不到 A):
  • 至少 1 張 Confusion Matrix / mAP 曲線 / 延遲對照表
  • 至少 1 個 baseline 對比

③ Demo 影片 (30-90 秒)

  • 手機錄屏 + 旁白(可用 Loom / OBS / 手機內建)
  • 展示 App 主要功能,別只放成功 case
  • 含失敗 case 展示(誠實面對演算法限制 — 這是專業度的展現)
  • 影片末尾顯示 GitHub repo 連結
  • 可上 YouTube 或直接交檔案

評分準則(占學期 20%)

維度比重A 級(85+)B 級(70-84)
技術深度30% 方法合理且有挑戰性,工具選擇有道理 能跑通但方法選擇隨意
實驗嚴謹30% 有 test set、定量指標、baseline 對比、Confusion Matrix 有結果但無 baseline 或無 confusion matrix
創意與應用20% 解決真實問題、有差異化、組合不同範式 常見題目,執行尚可
報告品質10% 八段完整,limitations / future work 寫到位 段落齊但 limitations 沒寫
Demo 完整度10% 30-90 秒清楚示範,含失敗 case,GitHub 一鍵可重現 有影片但 GitHub 缺東西

過去常見方向(僅供參考,不要照抄)

運動分析

籃球投籃軌跡追蹤、瑜伽姿勢檢查、跑步姿態分析

無障礙輔助

盲人辨識路標、手語翻譯、輪椅族 AR 導航

產線品質

瑕疵檢測、零件分類、包裝計數

農業

水果成熟度、害蟲識別、雜草偵測

互動娛樂

AR 濾鏡、手勢遊戲、寵物伴讀

個人應用

植物辨識、寵物追蹤、字幕產生、隱私模糊化

給學生的建議

  • 誠實面對 limitations:寫出失敗情境,比假裝完美更專業
  • 表格 + 圖優於文字:報告 1 張好圖勝過 1000 字
  • Demo 影片少話多畫面:30 秒讓人看到你做了什麼
  • GitHub README 寫好:讓老師可以一次跑通,加分關鍵
  • 不要解釋為什麼沒做:把時間花在做了什麼上
  • 過完整實驗流程:不要只跑一次就交,重複實驗看穩定性
  • 對自己作品 proud:你已經跑完整門課,值得驕傲
