MediaPipe vs YOLO 分工

同樣都是「在影像上找東西」,但不同抽象層級:

YOLO (W11)MediaPipe (W12)
輸出bbox + class骨架點 (21 點 / 33 點)
適用萬用偵測(任何物件)人類專用(手/身體/臉)
訓練要自訓Google 預訓練,直接用
RPS框出手 + 分類 rock/scissors/paper抓 landmark + 算彎曲度
細節整隻手是一個框每根手指都看得到

MediaPipe Hands 內部架構(兩階段)

跟單階段 YOLO 不同,MediaPipe Hands 是經典兩階段流程:

階段一:Palm Detector

  • 輕量 detection 模型
  • 找出手掌位置 (bounding box)
  • 每幀都跑(或追蹤模式時隔幾幀跑)

階段二:Hand Landmark

  • 用 palm bbox 裁切出手部 ROI
  • 跑專門模型回歸 21 個 landmark
  • 含 (x, y, z) — z 是相對深度

21 點 landmark 與 RPS 彎曲度算法

每隻手 21 點,從手腕到指尖。指縫分布:

0 = 手腕 1-4 = 大拇指 5-8 = 食指 9-12 = 中指 13-16 = 無名指 17-20 = 小指

RPS 彎曲度算法

每根手指看「掌根→第一節→指尖」三點是否大致共線:

  • 共線 → 該手指伸直
  • 明顯彎折 → 該手指彎曲

判斷規則:

  • 0 根手指伸直 → 石頭
  • 2 根手指伸直(食指+中指)→ 剪刀
  • 5 根手指伸直 → 布
對比 W9 凸缺陷法:W9 看「指縫深度與角度」靠形態學,W12 直接拿到 landmark 算彎曲度。本質不同 — landmark 已經是「結構化資訊」,W9 還在「像素層」。

Action Recognition:從靜態到動態

RPS 是靜態手勢。MediaPipe + Sequence Model 可以處理動態手勢(揮手、招手、特定動作):

  • 連續 N 幀 landmark 序列 (shape: (N, 21, 3))
  • 用 LSTM / Transformer / 1D CNN 分類
  • 應用:手語識別、無接觸控制、運動姿勢評估

期末專題可朝這方向延伸。

Android Tasks API 部署

MediaPipe 在 Android 有專門 SDK Tasks API(不走 Chaquopy,不走 TFLite,有自己 wrapper):

// build.gradle
implementation 'com.google.mediapipe:tasks-vision:0.10.x'
// Java
HandLandmarker landmarker = HandLandmarker.createFromOptions(...);
HandLandmarkerResult result = landmarker.detect(mpImage);
List<NormalizedLandmark> hand = result.landmarks().get(0);

輸出直接是 landmark 結構,Java 端跑彎曲度算法 → 輸出 RPS。
