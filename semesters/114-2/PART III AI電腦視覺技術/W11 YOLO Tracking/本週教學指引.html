物件偵測演進(RCNN → YOLO)

從「找哪裡有東西」變成「找 + 分類」一步完成:

  • R-CNN (2014):Selective Search 提 region + CNN 分類。慢
  • Fast R-CNN (2015):RoI Pooling 共用特徵。快一點
  • Faster R-CNN (2015):Region Proposal Network。再快
  • YOLO (2016):一刀切,直接 grid 預測。從 two-stage 變 one-stage
  • YOLOv5/v8/v11:工業界事實標準,容易訓練 + 部署

物件偵測的評估指標(W10 升級版)

IoU (Intersection over Union)

預測框與真實框的重疊面積 / 聯集面積。IoU > 0.5 才算「對」。

mAP (mean Average Precision)

不同 IoU 閾值下的平均 precision。業界標準,paper 必交。

NMS (Non-Maximum Suppression)

同一物件可能被預測多次,用 IoU 過濾保留最高信心那個。

FPS 與延遲

嵌入式系統的硬性指標 — 模型再強,跑不到 10 FPS 沒實用價值。

Android Java TFLite 部署 ⭐ 本週主菜

W10 路線 C/D 因為 tflite-runtime 沒 cp310 wheel,被迫走 Colab Local Runtime。本週跳過 Chaquopy,直接用 Java TFLite API(業界正解):

// Java 端
Interpreter tflite = new Interpreter(modelFile);
tflite.run(inputBuffer, outputBuffer);

關鍵工程坑

  • Input shape 不符:先用 interpreter.getInputTensor(0).shape() 確認
  • NMS 後處理:export 時加 nms=True,省 Java 端 NMS 邏輯
  • 推論慢:Interpreter.Options().setNumThreads(4) 或 GPU delegate
  • OOM:大模型 + Bitmap 雙重消耗,注意釋放 ImageProxy

Tracking 觀念與應用

偵測 = 每幀獨立找物件;追蹤 = 跨幀知道是同一個。應用:

  • 雙手對戰 RPS — 知道左手選了什麼、右手選了什麼
  • 運動分析 — 球員軌跡
  • 監視系統 — 追隨可疑人物
  • Action Recognition — 看一段軌跡判斷動作

現代 MOT (Multi-Object Tracking)

  • SORT (Bewley 2016):Kalman + Hungarian 匹配
  • DeepSORT (Wojke 2017):+ Re-ID 特徵
  • ByteTrack (Zhang 2022):每個 detection 都用,效果好且快
