本週流程(3 小時)

時段活動
0-15 分鐘說明流程 + 報告順序抽籤
15-165 分鐘每組 8-10 分鐘 demo + 5 分鐘 Q&A(依組數調整)

175-180 分鐘結業致詞 + 學期總結

期末三件套

① 程式碼(GitHub repo)

  • 完整 Android 專案(可重現 build)
  • README 含 build 指令、相依套件、模型權重位置
  • 有訓練 notebook 的話一併放
  • 授權聲明(預設 MIT)

② 研究報告(PDF, 10-15 頁)

每個段落必有,可長可短:

  • Abstract — 一段話講完問題與結果
  • Introduction — 為什麼這個題目重要
  • Method — 你的演算法 / 模型架構
  • Experiments — 資料集、訓練設定
  • Results — 數據表 + 視覺化 + Confusion Matrix / mAP
  • Discussion — 結果意義 + 跟 baseline 比較
  • Limitations — 你的方法在什麼情境會失敗
  • Future Work — 如果你有更多時間 / 資料 / 算力會怎麼做
研究級門檻:至少 1 張 Confusion Matrix / mAP 曲線 / 延遲對照表;至少 1 個 baseline 對比。

③ Demo 影片(30-90 秒)

  • 手機錄屏 + 旁白
  • 展示 App 主要功能
  • 含失敗 case 展示(誠實面對你的演算法限制)
  • 影片末尾顯示 GitHub repo 連結

評分標準(占學期 20%)

維度比重看什麼
技術深度30%用到的方法是否合理、有挑戰性
實驗嚴謹30%是否有 test set、定量指標、baseline 對比
創意與應用20%是否解決真實問題、有差異化
報告品質10%PDF 報告含 spec、limitations、future work
Demo 完整度10%30-90 秒影片清楚示範、GitHub 可重現
研究方法是評分骨幹:不只看「跑得通」,更看「跑得有道理」。confusion matrix、baseline 對比、limitation 分析,缺一不可拿高分。

給學生的最後建議

  • 誠實面對 limitations:寫出哪些情境會失敗,比假裝完美更專業
  • 表格 + 圖優於文字:報告 1 張好圖勝過 1000 字
  • Demo 影片少話多畫面:30 秒讓人看到你做了什麼
  • GitHub repo 寫好 README:讓老師可以一次跑通
  • 不要解釋為什麼沒做:把時間花在做了什麼上
  • 對自己作品 proud:你已經跑完整門課,值得驕傲
